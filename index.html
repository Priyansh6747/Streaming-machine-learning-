    Major Project — Streaming machine learning : Drift detection and adaptation¶

    Research-based project on machine learning from data streams, using River as the experimental framework.

    Status: Phase 0 (research) complete, Phase 1 (experimentation) in progress — the first pilot (Exp-01) has been run.

    The one-paragraph version¶

    Almost all machine learning you've been taught assumes the dataset is a finished object: it sits on disk, you load it, you split it, you fit a model, you're done. Streaming machine learning drops that assumption. Data arrives one sample at a time, potentially forever, and is too large (or too fast) to store. The model must learn incrementally, in a single pass, using bounded memory. And because the world generating the data keeps changing, the model must also notice when it becomes wrong and adapt. That last part — concept drift, and specifically the cost of delayed labels (the "Delay Tax") — is the real research problem, and it's what makes this a project rather than a tutorial.

    The picture¶

    flowchart LR
    S["Data stream<br/>x1, x2, x3, ... (never ends)"] --> P["predict_one(x)<br/>1. TEST"]
    P --> M["metric.update(y, y_pred)<br/>2. SCORE"]
    M --> L["learn_one(x, y)<br/>3. TRAIN"]
    L --> D{"Drift<br/>detector"}
    D -- "no drift" --> S
    D -- "DRIFT!" --> R["Adapt:<br/>reset / retrain / reweight"]
    R --> S

    Each sample is used for testing before it is used for training, then thrown away. The model is never "finished" — it is permanently mid-training.

    Phase 1 — Experimentation¶

    • Roadmap v2 — DF-H — the new ultimate goal: a label-free deep monitor plus supervised confirmation, targeting the KDD'26 detector benchmark and the delayed-label setting.
    • E01 — Metric v2 correction — the current headline: frozen recovered 0/11, DeepRiver's corrected damage_ref is 74.8 vs 515.0 samples·κ (≈6.9×), and the legacy 294× is retired as an upper bound.
    • E03 — Baseline ladder — at 11 seeds and 220 runs, every streaming adapter pays less drift damage than frozen and than every scheduled-retrain clock; the phase-noise test remains inconclusive because the refit buffer dominates the 1k/5k clocks.
    • E04 — Detector map — the synthetic map: eight detectors across four drift shapes and four generators; HDDM-A on the raw signal is the best default on the static host, recurring drift is the hard case, and smoothing raises false alarms.
    • E14 — Real-stream model check — ARF leads both real datasets and the deep model does not beat it: the evidence for using DriftFormer as a signal extractor, not the host. Provisional five-seed slice with acceptance rules.
    • E17 — Real-stream detector map — the same eight detectors on real Elec2 records; HDDM-A keeps its four-shape win on the static host, but ADWIN wins abrupt and recurring on the adaptive host, so the default is host-conditional.
    • E18 — Deep signal gate — the pre-registered AUC gate failed (best deep 0.616 vs error 0.598), but at 0.1/1k FAR the feature signals detect feature drift earlier than error and detect feature filtering where error is blind; the classical KS control is competitive.
    • E19 — DF-H v1 pilot — DF-H ranks 3rd overall (7.09) behind STEPD and SEED; FAR passes and it beats the no-feature control, but top-2 and the primary feature-cell test fail. The full E20 matrix is not run.
    • E21 — Delay Tax detector — the surviving headline: at L = 2,000, label-free Stage 1 warns in 70–513 samples while SEED/STEPD take 2,120–2,710 and ADWIN 2,472–3,269. The error-only panel pays the label tax; Stage 1 does not.
    • E22 — Detector shootout — the direct capability check on our data: DF-H is 3rd overall (7.34), ahead of HDDM-W, ADWIN, HDDM-A and PageHinkley; only SEED/STEPD lead. It owns feature permutation against the requested panel, with 0.04 FAR.
    • Exp-01: DeepRiver rolling vs frozen batch on SEA — the first atomic experiment (legacy metric; superseded by E01).
    • Exp-02: the 11-seed sweep — the sweep that made the claim statistical (legacy metric; corrected by E01).
    • Thesis: how streaming beats batch, and on what — the mechanism and the metric family where the win is structural.
    • Streaming vs Batch: real metrics where online learning wins (and where it doesn't) — evidence dossier + the Ch1 experimental protocol.
